# Orb Oracle Solidity Agent Guidelines

This repository contains the Solidity smart contracts for the Orb Oracle protocol. Refer to this file for compilation, style conventions, and architecture constraints.

---

## Tech Stack
- **Framework:** Foundry (Solc `^0.8.20`)
- **Dependencies:** OpenZeppelin Contracts, `forge-std`

---

## Commands
- **Build:** `forge build`
- **Test:** `forge test`
- **Gas Report:** `forge test --gas-report`
- **Format Check:** `forge fmt --check`
- **Format Code:** `forge fmt`

---

## Architecture & Code Style

### 1. Fixed-Point Math (`WAD`)
All price feeds are normalized to **18 decimals**. Use `WAD = 1e18` for scaling fixed-point operations:
- **Multiplication:** `(valA * valB) / 1e18`
- **Division:** `(valA * 1e18) / valB`
- **Inversion:** `(1e18 * 1e18) / val`

### 2. Custom Errors
Always use Solidity custom errors instead of `require` statements with strings. Declare them globally or at the top of contracts:
```solidity
error InvalidSampleSize();
// CORRECT
if (sampleSize == 0) revert InvalidSampleSize();
// WRONG
require(sampleSize > 0, "invalid sample size");
```

### 3. State & Constructor Validations
Move static immutable validations (e.g. checking default lookback parameters $> 0$) out of view functions and place them directly inside the constructor to optimize runtime gas usage.

---

## Boundaries
- **Dependencies:** Never modify files under `lib/` (OpenZeppelin or `forge-std`).
- **Autogenerated files:** Never modify JSON files under `out/` or `cache/`.
- **Environment:** Do not commit `.env` or any file containing private keys.

---

## Git Workflow
- **Commit Format:** Follow the **Chris Beams Git Commit Message** guide (imperative subject, capitalized, under 50 characters, wrapped body).
- **Branch Format:** `feat/short-desc`, `fix/short-desc`, or `refactor/short-desc`.
